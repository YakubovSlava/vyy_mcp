Структура файлов навыка

Как навык выглядит на диске

Каждый навык — это папка в общей директории с навыками (путь показан в диалоге «⚙» на вкладке «Навыки»). Есть два вида навыков, которые различаются по тому, какой файл лежит в корне папки — никакого отдельного manifest.json не нужно ни для одного из них. В одной общей директории могут сосуществовать оба вида:

{{ shared_dir }}/tools/ <имя-code-навыка>/ <любое-имя>.py (единственный .py-файл — сам себе манифест) <имя-doc-навыка>/ SKILL.md (или skill.md) ... любые другие сопутствующие файлы/папки

Code-навыки: один .py-файл — и всё

Code-навык — это один файл .py (с любым именем) с ровно одной функцией верхнего уровня. Отдельный manifest.json не нужен — сама функция и есть манифест:

# tool.py
def echo(text: str, shout: bool = False) -> str:
    """Echoes the given text back, optionally shouting it."""
    return text.upper() if shout else text
  • Имя функции становится именем навыка и MCP-инструмента — должно соответствовать [a-z0-9][a-z0-9_-]+ (обычный snake_case уже подходит).
  • Docstring функции становится описанием навыка — обязателен, без него установка будет отклонена.
  • Входная схема MCP выводится из аннотаций типов параметров функции — отдельно описывать её не нужно.
  • Версия — необязательная строка __version__ = "1.2.3" на уровне модуля; если её нет, используется 1.0.0 по умолчанию.
  • В архиве/папке должен быть ровно один .py-файл в корне — если функций несколько или файл не один, установка будет отклонена с понятной ошибкой.

Doc-навыки: SKILL.md

У doc-навыка нет кода на Python — это файл SKILL.md, обычный markdown-текст без какого-либо специального синтаксиса (никакого YAML-заголовка не нужно — пишите так, как обычно пишете инструкцию), плюс любые сопутствующие файлы, на которые ссылается текст.

# Repo explainer

... инструкции для агента здесь ...

See `references/architecture.md` for more detail, or call this skill
again with `file="references/architecture.md"` to read it directly.

Имя и описание навыка задаются не в файле, а в форме «Добавить навык» при загрузке — это осознанный выбор: писать YAML-заголовок в markdown-файле вручную неудобно и редко у кого получается с первого раза.

  • Имя — уникальный слаг ([a-z0-9][a-z0-9_-]+), он же имя MCP-инструмента и имя папки навыка.
  • Описание — становится собственным описанием MCP-инструмента, чтобы подключившийся агент мог решить, когда вызывать его, только по tools/list — пишите с акцентом «когда это нужно использовать», а не «что это делает».
  • Текст плюс остальные файлы в папке (references/, изображения и т.д.) раскрываются постепенно, а не отдаются целиком за один ответ — см. следующий раздел.

Вызов doc-навыка: постепенное раскрытие

  • Вызов инструмента без аргументов возвращает текст SKILL.md плюс список остальных файлов в папке навыка.
  • Повторный вызов с аргументом file, равным одному из этих путей, возвращает содержимое этого файла как текст.

Это делает первый ответ инструмента небольшим — агент подгружает дополнительные файлы только тогда, когда они реально нужны для задачи. Полноценный рабочий пример лежит в examples/repo_explainer/.

Три способа установить навык

  • Загрузить .zip через «+» на вкладке «Навыки» — в корне архива должен быть либо один .py-файл (code-навык), либо SKILL.md/skill.md (doc-навык). Архив можно собрать и как зазипованную папку (myskill/SKILL.md, а не SKILL.md в корне) — такая единственная оборачивающая папка определяется автоматически и убирается при установке.
  • Написать навык прямо в админке — кнопка «✎ Написать навык» рядом с «+»: только для doc-навыков, без архива вообще. Указываете имя, описание и текст SKILL.md в одной форме — файл создаётся на сервере сразу.
  • Положить папку напрямую в {{ shared_dir }}/tools/<имя-навыка>/ на диске — загрузка через интерфейс не нужна, работает точно так же.

Редактирование описания doc-навыка

У установленного doc-навыка кнопка «Редактировать» на вкладке «Навыки» позволяет поменять описание без переустановки всего архива — текст SKILL.md и сопутствующие файлы при этом не трогаются. У code-навыков такой кнопки нет — их описание это docstring функции в .py-файле, меняется прямым редактированием файла на диске.

Как быстро появляются изменения

  • Вкладка «Навыки» читает директорию заново при каждой загрузке страницы — изменения видны сразу после обновления.
  • MCP-сервер (к которому обращаются реальные агенты/пользователи) пересканирует директорию каждые 5 секунд и автоматически регистрирует/удаляет инструменты — перезапуск не нужен, независимо от того, пришло ли изменение через загрузку «+» или через прямое редактирование файлов на диске.

Проверка при установке — только структурная (валидный zip/папка; для code-навыков — ровно один .py-файл с одной функцией и docstring; для doc-навыков — указаны имя и описание в форме, текст SKILL.md не пустой) — код не выполняется во время проверки, только когда клиент реально вызывает инструмент.

Возврат нескольких файлов для самостоятельного запуска человеком

Навык может возвращать не только строку — любое JSON-сериализуемое значение отправляется прямо в ответе MCP. Используйте это для навыка, который должен отдать файлы вызвавшему его человеку, чтобы он сохранил и запустил их под своей учётной записью, вместо текстового ответа. Сервер здесь ничего не исполняет сам — та же идея, что и в ноутбуке подключения к Bitbucket.

from jupyter_mcp_tools.common.skill_results import SkillFile, files_result

def make_setup_files(project_name: str) -> dict:
    return files_result(
        f"Setup files for {project_name}. Save and run these yourself.",
        [
            SkillFile("setup.sh", "#!/bin/bash\necho hi\n", run_hint="bash setup.sh"),
            SkillFile("config.yaml", f"project: {project_name}\n"),
        ],
    )

Форма ответа: {"message": ..., "files": [{"filename", "content", "run_hint"}, ...]}. Полноценный рабочий пример лежит в examples/setup_files_tool/.
